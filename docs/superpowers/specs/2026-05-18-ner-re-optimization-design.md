# NER 模型优化 & RE 扩展设计方案

## 背景

当前基于 BERT 的 NER 模型存在以下问题：

- **边界漂移**：如"GB/T3191-2019"识别为国标但边界不完整，"Φ20H7"中的"20"被误识别为工艺
- **实体标签覆盖不全**：只覆盖 4 类（零件、工艺、材料、国标），缺少尺寸公差、粗糙度、设备、工序编号等
- **训练数据模板化**：1900 条数据中大量为简单模板句式（如"操作人员需严格按照XXX工艺规范执行"重复 64 次），导致模型在真实复杂文档上泛化不足
- **短实体主导**：实体平均长度仅 7 字符，模型倾向于抽取过短的片段

## 目标

- NER 准确率 ≥ 95%（Entity F1 严格匹配），边界不漂移
- RE 准确率 ≥ 90%
- 推理速度 < 500ms / 1000 字文档

## 一、标签体系与关系设计

### 9 类实体标签

| # | 标签名 | 示例 | 说明 |
|---|--------|------|------|
| 1 | `零件` | 液压阀体、推力球轴承、内六角螺栓 | 机械零部件 |
| 2 | `工艺` | 珩磨、精镗、攻丝、锯切定长 | 加工工艺/工序 |
| 3 | `材料` | 6061-T6、丁腈橡胶 NBR、石墨 | 原材料 |
| 4 | `标准编号` | GB/T 1172-1999、ASTM A240-304 | 不带书名号的编号 |
| 5 | `标准全称` | 《ASTM A240-304 压力容器用不锈钢板材》 | 含书名号的完整名称 |
| 6 | `尺寸公差` | Φ20H7、M8×1.25、±0.1mm | 尺寸/公差规格 |
| 7 | `粗糙度` | Ra 0.8μm、Rz 3.2μm | 表面粗糙度参数 |
| 8 | `设备` | VMC-850、金刚石镗刀、三坐标测量仪 | 加工设备/刀具/量具 |
| 9 | `工序编号` | OP05、OP40、OP50 | 工序编号 |

共计 19 个 BIO 标签（O + B×9 + I×9）。

### 3 种关系类型（RE）

| 关系 | Subject → Object | 示例 |
|------|-------------------|------|
| `has_material` | 零件 → 材料 | 液压阀体 → 6061-T6 |
| `has_process` | 零件 → 工艺 | 液压阀体 → 精镗内孔 |
| `uses_equipment` | 零件/工艺 → 设备 | 液压阀体 → VMC-850 |

### 标注原则

- 实体不嵌套，同一字符位置只属于一个实体
- 「标准编号」与「标准全称」在数据中严格区分：有书名号的标全称，无书名号的标编号
- 「工序编号」与「工艺」独立标注，如"OP40"是工序编号，"精镗Φ20H7内控"是工艺
- 一个零件可以有多个材料、多个工艺、多个设备

## 二、数据策略

### 旧数据清洗

- **高频模板去重**：同一模板（如"操作人员需严格按照XXX规范执行"）保留不超过 20 条变体
- **空样本压缩**：237 条空样本保留约 80 条（保证模型能预测 O）
- **短实体过滤**：1 字符实体移除或扩展为完整词
- **标签映射**：「国标」→ 按书名号规则拆分为「标准编号」+「标准全称」
- **序号重排**：spans 中 id 从 1 开始重新编号，确保唯一

### 新数据补充

- **真实文档长句**：300+ 条，从实际工艺文档/技术文件中标注，50-150 字符，含多实体混合
- **合成长句**：150+ 条，用模板随机组合不同类别实体，增强泛化
- **边界难例**：50+ 条，聚焦 Φ/H7/M/Ra 等易混淆的尺寸规格

### 最终数据构成

- 清洗后旧数据：~1200 条
- 新增数据：500+ 条
- 总计：1700+ 条
- 划分：训练 80% / 验证 10% / 测试 10%

### 标注格式（JSONL）

```json
{
  "text": "液压阀体选用6061-T6铝合金棒料，执行GB/T 3191-2019标准",
  "spans": [
    {"id": 1, "start": 0, "end": 4, "label": "零件"},
    {"id": 2, "start": 6, "end": 17, "label": "材料"},
    {"id": 3, "start": 22, "end": 36, "label": "标准编号"}
  ],
  "relations": [
    {"head": 1, "tail": 2, "label": "has_material"}
  ]
}
```

## 三、模型架构与训练策略

### 架构

```
输入文本
    ↓
chinese-roberta-wwm-ext (12层 Transformer Encoder)
    ↓
    ├──→ NER Head: Linear(768→19) → CRF → BIO标签序列
    │
    └──→ [阶段2] RE Head: 实体对特征拼接 → 关系分类
```

### 核心改进

| 项目 | 当前 | 新方案 |
|------|------|--------|
| 预训练模型 | bert-base-multilingual-cased | chinese-roberta-wwm-ext |
| 解码层 | Linear → Softmax | Linear → CRF |
| 损失函数 | CrossEntropy | CRF NLL + 可选 Focal Loss |
| 对抗训练 | 无 | FGM（embedding 扰动） |
| 评估 | 无 | 验证集 Entity F1 + Boundary F1 |

### 选型理由

- **chinese-roberta-wwm-ext**：全词掩码对中文实体边界更敏感，且对中英混合文本（GB/T、ASTM、Φ20H7）子词切分更优
- **CRF**：显式建模标签间转移概率，禁止非法标签序列（如 B-国标 → I-材料），从建模层面解决边界漂移
- **FGM**：增强对 OCR 噪声（空格、标点变体）的鲁棒性

### 训练超参数

| 参数 | 值 |
|------|-----|
| epochs | 5-8 |
| batch_size | 16 |
| learning_rate | 2e-5 |
| warmup_ratio | 0.1 |
| max_length | 256 |
| weight_decay | 0.01 |
| 梯度裁剪 | 1.0 |
| 优化器 | AdamW + Cosine Scheduler |

### 评估指标

| 指标 | 目标 |
|------|------|
| Entity F1（严格匹配：边界+标签） | ≥ 95% |
| Entity Precision | ≥ 95% |
| Entity Recall | ≥ 95% |
| Boundary F1（边界正确，标签宽容） | ≥ 97% |
| 每类 F1（macro avg） | ≥ 90% |

## 四、RE 实施方案

### 策略：Pipeline 两阶段

- 阶段1：NER 稳定达到 95% F1
- 阶段2：在 NER 基础上叠加 RE 模型

### RE 模型

```
Roberta Encoder（与 NER 共享，可冻结）
    ↓
实体对 span embedding 提取（[CLS] + 起止位置平均池化）
    ↓
拼接：[实体1 emb; 实体2 emb; 距离分桶 emb]
    ↓
Linear(3×768 + 距离 → 64) → ReLU → Dropout → Linear(64 → 4)
    ↓
4 类输出: has_material / has_process / uses_equipment / no_relation
```

### 关键实现

- 实体对生成：同句内两两组合，token 距离 > 50 的过滤
- 负样本：`no_relation` 占绝大多数，使用 focal loss 或下采样平衡
- 距离嵌入：分桶（0-2, 3-5, 6-10, 11-20, 21+），学习位置偏好
- Pipeline 推理：NER 先抽取实体列表，RE 再对所有实体对分类

## 五、实施路径

### M1: 数据准备

- 旧数据标签映射（国标 → 标准编号 + 标准全称）
- 高频模板清洗，去重去噪
- 短实体过滤与修正
- 新数据标注（真实文档 300+ 条 + 合成 150+ 条 + 难例 50+ 条）
- 数据集 8:1:1 划分

### M2: 模型开发

- 替换预训练模型为 chinese-roberta-wwm-ext
- 实现 CRF 解码层（torchcrf 或手写）
- 添加 FGM 对抗训练
- 添加评估脚本（Entity F1, Boundary F1, 每类 F1）
- 兼容现有 API 接口（train_model / run_inference / continue_train）

### M3: 训练与调优

- 新数据 + 新模型基线训练
- 超参调优（lr, batch_size, epochs）
- CRF 消融实验（对比有无 CRF 的边界指标）
- 未达标时针对性补充数据

### M4: RE 实现（NER 稳定后）

- 标注关系数据
- 实现 RE 模型训练 + 推理
- NER → RE Pipeline 串联
- 联合端到端评估
